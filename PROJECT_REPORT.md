## Abstract
This project analyses retail transactions and forecasts future daily sales. It cleans invoice records, aggregates daily sales, performs exploratory and time-series analysis, evaluates Naive, ARIMA, and SARIMA models, and presents the output in a Streamlit dashboard. Metrics and forecasts are generated by the program and saved under `outputs/`; they must be regenerated when a different dataset is used.

## Introduction, Problem Statement, and Objectives
Historical transactions contain useful demand information, but invoice-level data is not easy to interpret directly. The project transforms it into a daily series so that trends, weekly patterns, and future sales can be examined. Its objectives are to prepare reliable sales data, visualise sales behaviour, compare models using test data, and forecast 30 future days.

## Literature / Background
Time-series forecasting uses observations ordered by time. Trend is the long-term movement, seasonality is a recurring pattern, and residual/noise is unexplained variation. ARIMA models autocorrelation and differencing; SARIMA adds repeating seasonal behaviour. A baseline forecast is necessary to confirm that a more complex model genuinely improves results.

## Dataset Description
The recommended source is UCI Online Retail, a UK retailer transaction dataset. It includes InvoiceNo, StockCode, Description, Quantity, InvoiceDate, UnitPrice, CustomerID, and Country. C-prefixed invoice numbers represent cancellations. The bundled sample is synthetic and only used for testing; it is not real-world evidence.

## System Requirements
Python 3.10+, Pandas, NumPy, Matplotlib, Plotly, scikit-learn, statsmodels, Streamlit, and openpyxl. A standard laptop with 4 GB RAM is sufficient for the sample data.

## Methodology and Data Preprocessing
The pipeline validates required columns, parses dates, removes cancellations, removes rows with missing dates or non-positive quantity/price, and calculates `SalesAmount = Quantity × UnitPrice`. It then groups transactions by date, fills dates without sales with zero, and sorts chronologically. These removals are documented in `outputs/metrics/data_summary.json` after each run.

## Exploratory Data Analysis
The project reports dataset properties, missing values, sales totals, total quantity, products, customers, transactions, top products, country sales, monthly sales, daily sales, and a 30-day rolling average. Saved visualisations are in `outputs/figures/`.

## Time-Series Analysis
The daily series is decomposed with a 7-day seasonal period when adequate data exists. An ADF test is saved to `outputs/metrics/adf_result.csv`; a low p-value suggests stationarity. Stationarity matters because ARIMA assumes stable statistical behaviour; differencing (`d=1`) helps model changing-level series.

## ARIMA and SARIMA
ARIMA(1,1,1) uses one autoregressive lag, first differencing, and one moving-average term. SARIMAX(1,1,1)(1,0,1,7) adds a weekly seasonal component suited to daily retail data. These are small, explainable configurations rather than a large parameter search.

## Model Evaluation and Results
The last 15% of the series is held out chronologically. MAE measures average absolute error, RMSE penalises larger errors, and MAPE reports relative error while excluding zero actual values. Actual generated results are saved in `outputs/metrics/model_comparison.csv`; the program selects the lowest-MAE model. No results should be written manually into this report.

## Dashboard
The dashboard has Overview, Sales Analysis, Time-Series Analysis, Forecasting, Model Performance, and Data tabs. It reads only generated output files and shows a helpful message if the pipeline has not been run.

## Limitations, Future Scope, and Conclusion
The sample data is synthetic; real conclusions require UCI data or another verified source. ARIMA-family models do not include promotion, price changes, holidays, or stock availability. Future work may forecast each product, add external features, compare more models, and deploy online. The project demonstrates an understandable end-to-end forecasting workflow for academic use.
